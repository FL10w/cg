Базовое задание на оценку 3 из [условия](materials/assignment.pdf), на основе второй лабораторной: C++20, Vulkan, GLFW и Dear ImGui. На тор наложена одна текстура альбедо из файла `assets/torus.bmp`. Камера и освещение Блинн–Фонга сохранены из предыдущей работы. Дополнительные задания не включены.

Отчёт: [PDF](report/314_Шитов_Лаб3.pdf) · [DOCX](report/314_Шитов_Лаб3.docx). Текстура в материалах: [исходный BMP](materials/torus.bmp) · [PNG для просмотра](materials/torus.png).

## Сборка и запуск на Linux

Из папки `cg/lab3`:

```bash
bash build.sh
bash run.sh
```

Команда сборки также запускает тесты геометрии и камеры. Локальные SDK и кеш исходников библиотек используются из `.local/`, затем из `../lab2/.local/` или `../lab_01/.local/`, если собственный каталог отсутствует. Папка лабораторной содержит свои исходники, шейдеры, текстуру и шрифт.

Нужны C++20, CMake 3.20+, Git, заголовки и загрузчик Vulkan, `glslc`, Vulkan-драйвер и заголовки X11. Для Debian/Ubuntu:

```bash
sudo apt install build-essential cmake git libvulkan-dev glslc vulkan-validationlayers \
    libx11-dev libxrandr-dev libxinerama-dev libxcursor-dev libxi-dev libxfixes-dev libxrender-dev
bash build.sh
bash run.sh
```

Без прав администратора можно использовать `bash tools/setup-local.sh`, как в прошлых лабораторных. Для него уже должны быть доступны apt-репозитории, компилятор, CMake, Git, `libx11-dev` и Vulkan-драйвер. В Wayland-сеансе нужен XWayland.

При первой сборке CMake скачивает GLFW 3.4, vk-bootstrap v1.4.321, VMA v3.4.0, ImGui v1.92.9 и stb по закреплённому коммиту `4e9b368bfc071e97206ea5c6adba68dd0cbf8897`. Для загрузки текстуры используется `stb_image`.

## Сборка на Windows

`build.sh` и `run.sh` предназначены для Linux. В Windows команда `bash` может запускать WSL; устанавливать WSL для этой программы не требуется.

На текущем компьютере уже есть готовая Windows-сборка. Из `cg/lab3` в CMD или PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1
```

`run.ps1` ищет Windows-приложение в каталогах сборки рядом со скриптом и передаёт ему аргументы. Готовые сборки и локальные инструменты исключены из Git; на другом компьютере приложение нужно собрать заново.

Нужны Visual Studio 2022 с C++, CMake, Git и Vulkan SDK. Из этой папки:

```powershell
cmake --preset msvc-debug
cmake --build build-msvc-debug --config Debug --parallel 4
ctest --test-dir build-msvc-debug -C Debug --output-on-failure
.\build-msvc-debug\Debug\cg-lab-03.exe
```

Полная сборка и запуск проверены на Windows с MinGW-w64 (GCC 16.2) и NVIDIA GeForce RTX 4070, включая загрузку текстуры и изменение размера окна. Пресет Visual Studio отдельно не проверялся. Пути к шейдерам и ресурсам задаёт CMake: после сборки рабочая директория запуска произвольная. После переноса исходников на ноутбук нужно собрать программу заново.

## Управление

Панель ImGui позволяет менять положение и поворот камеры, угол обзора, плоскости отсечения и скорость; направление, цвет и интенсивность единственного направленного источника; фоновое освещение; цвет и коэффициент блика. Альбедо берётся из одной текстуры.

В области сцены: ПКМ поворачивает камеру, WASD перемещает вперёд/назад и в стороны, Q/E — вниз/вверх, Shift ускоряет движение, колесо меняет угол обзора. `Esc` закрывает окно. Кнопки сброса восстанавливают настройки камеры либо света и материала.

## Выполнение базового задания

- Изображение `assets/torus.bmp` загружается из файловой системы и декодируется сторонней библиотекой `stb_image`.
- Вершина содержит позицию, нормаль и UV. Координаты тора вычисляются вместе с геометрией; вершины на обоих швах дублируются для корректной интерполяции UV от 0 до 1. Получается 2145 вершин и 4096 треугольников.
- Вершинный и индексный буферы размещаются в памяти GPU. Данные загружаются через временные staging-буферы и команды копирования. Текстура загружается в GPU аналогично.
- Используется один набор дескрипторов: binding 0 — динамический uniform-буфер, binding 1 — одна пара изображение–сэмплер. Смещение записи объекта передаётся в `vkCmdBindDescriptorSets`; шаг записей учитывает `minUniformBufferOffsetAlignment`. На сцене один объект, поэтому массив свойств содержит одну запись.
- Во фрагментном шейдере текстура задаёт альбедо для фоновой и диффузной составляющих освещения Блинн–Фонга. Push-константы, анимированные эффекты и дополнительные карты материала не используются.

## Проверка и файлы

CPU-тесты проверяют геометрию и ориентацию треугольников, нормали, UV и швы, выравнивание динамического UBO, а также камеру и проекцию Vulkan. Они выполняются в конце `bash build.sh`.

На текущем компьютере прошли CPU-тесты, компиляция обоих шейдеров через `glslc` для Vulkan 1.1 и проверка декодирования BMP через `stb_image`. Vulkan Validation Layers на этой Windows отсутствуют; запуск приложения здесь не заменяет проверку с ними на Linux.

Также прошли семь запусков на Windows: исходный ракурс с изменением размера окна, вид сбоку, широкий угол обзора и четыре настройки освещения. Проверены видимая текстура при одном фоновом освещении, сложение ambient и diffuse, блик и цвет источника. Реальные снимки и журналы сохранены в `checks/`, итог — [windows-render.log](checks/windows-render.log); [основной снимок](checks/screenshots/default.png).

Для проверки отрисовки на Linux предусмотрен `bash tools/verify.sh`; требуются Xvfb, xauth, Python с Pillow и Vulkan Validation Layers. Проверка сохраняет снимки и журналы в `checks/`. Проверка с Validation Layers на Linux здесь не выполнялась.

Сохранённые Windows-снимки можно повторно проверить без запуска приложения (нужен Pillow):

```bash
python3 tools/check_render.py --allow-missing-validation
```

Этот флаг разрешает проверку снимков с явно отмеченным отсутствием Validation Layers. Скрипт `tools/verify.sh` на Linux требует включённых слоёв проверки.

- `source/scene.hpp` — тор с UV, камера, освещение, материал и структура uniform-данных.
- `source/application.cpp` — интерфейс, ресурсы GPU, staging-загрузка, дескрипторы и отрисовка.
- `source/texture_image.cpp` — декодирование изображения через `stb_image`.
- `shaders/torus.vert`, `shaders/torus.frag` — передача UV и текстурированное освещение.
- `assets/torus.bmp` — единственная текстура альбедо.
- `tools/make_texture.py` — воспроизводимое создание комплектного BMP; при запуске приложения изображение читается из готового файла.
- `materials/assignment.pdf` — исходное условие.
- `materials/torus.bmp`, `materials/torus.png` — копия используемой текстуры и её PNG-представление.
- `report/314_Шитов_Лаб3.pdf`, `report/314_Шитов_Лаб3.docx` — отчёт по шаблону первой лабораторной, с формулами и четырьмя иллюстрациями.
- `tests/scene_tests.cpp` — CPU-проверки.

Отчёт можно пересоздать командой `py -3.11 tools/make_report.py` на Windows с установленными Word, `python-docx`, Pillow и `pywin32`. На Linux используется `python3 tools/make_report.py` с `python-docx`, Pillow и WeasyPrint. Содержание хранится в `tools/report_content.py`, титульный лист берётся из `materials/report_template.docx`. Генератор также сохраняет печатный HTML и копии скриншотов и журналов в `report/`.
